## Замечания (в работу следующего запуска, первыми задачами)
Major:
- M1. `app/logging.py:46` — рендер трейсбека с локальными переменными после редакции: `log.exception()` может вывести текст клиента и пароль БД. Исправление однострочное (проверено приёмщиком).
- M2. `app/services/outbox.py:610` + `ingest.py` — устаревший `@username` не обновляется при совпадении `tg_user_id`, а outbox предпочитает username → ответ может уйти на освобождённый чужой ник. Предпочитать ID/сущность автора; обновлять username.
- M3. `ingest.py:145` — один человек может стать двумя клиентами (сначала по нику, потом по ID у другого ника). Решается в миграции 0002 (идентичность по ID автора из MTProto).
- M4. Промежуточные WIP-коммиты не были самосогласованы (3 теста падали на старом HEAD) — закрыто этим коммитом.
Minor: порядок блокировок в стартовом sweep (`outbox.py:396`) может дедлокнуться с reassign; отменённый `execute_send` оставляет `sending` до рестарта; round-robin пропускает оператора при FK KEY SHARE; окно кандидатов может забиться одним заблокированным диалогом; отсрочка flood на уровне аккаунта не продлевает аренду; `release()` бросает WrongState вместо InvalidTransition; ValidationError конфигурации эхоит соседние значения .env; сироты-клиенты при гонке разных ссылок на одного человека.
