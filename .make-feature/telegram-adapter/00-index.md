## Понимание алгоритма владельца (трактовка, требует подтверждения)
- Владелец вручную пересылает 50–100 заявок в общий чат, где состоят оба аккаунта.
- Ссылка в заявке — текстовая (entity `text_url` под словом «сообщение»/«пользователь»): на исходное сообщение в группе или на пользователя.
- Обработка от новых к старым (сначала последнее сообщение чата).
- Аккаунты работают строго по очереди, никогда одновременно: A → пауза → B → пауза → A …; тайминги настраиваются.
- Перед отправкой — проверка «не тот же клиент»: точная по ID автора (через MTProto), запасная — по похожему тексту.
- После отправки аккаунт ставит ❤️ на заявку; заявки с реакцией пропускаются.

## Проверенные факты (Telethon 1.45.0, установлен во временный venv)
- `messages.SendMessageRequest` принимает `random_id`; есть `RandomIdDuplicateError` → основа для безопасного повтора после тайм-аута (гипотеза о семантике — проверить на test DC).
- Есть `messages.SendReactionRequest(peer, msg_id, reaction=ReactionEmoji)`.
- Есть `PeerFloodError`, `FloodWaitError`, `UserPrivacyRestrictedError`, `ChannelPrivateError`, `UserIsBlockedError`, `InputUserDeactivatedError`; `PrivacyPremiumRequiredError` в 1.45.0 нет (ловить по RPC-коду).
- `MessageEntityTextUrl(offset, length, url)` — скрытые ссылки доступны.
- TCP до тестового DC 149.154.167.40:443 из контейнера открыт.
- «300 сообщений в день с Premium» — со слов владельца; в документации Telegram такой лимит не найден → настройка, а не гарантия.

## Ответы владельца (2026-10-12)
| Вопрос | Ответ | Следствие |
|---|---|---|
| Дубль | «как и все не отвеченные сообщения оставить без реакции» | дубль → `cancelled`, `review_reason='duplicate'`, реакции нет |
| Повторный контакт | «Никогда больше не писать» | клиент, которому уже писали (любой аккаунт, по ID автора), → всегда дубль; плюс проверка истории диалога аккаунта |
| Тайминги | «1 раз в 2 минуты» | трактовка: одна отправка в системе раз в 120 с, аккаунты чередуются (каждый раз в 4 мин); настройка `SEND_INTERVAL_SECONDS=120`; суточный лимит на аккаунт — настройка, на пилоте низкий |
| Шаблон | «Показывать на подтверждение. Аккаунт сам может придумать ответ… так даже лучше, я задам тон» | черновик пишет Claude по тону владельца, без выдуманных цен/адресов/наличия; владелец подтверждает в боте (Отправить / Изменить / Пропустить) |
| Группы-источники | «Да» | оба аккаунта состоят в группах; недоступное сообщение → ручная проверка |
| Новая пачка | «Сначала новые» | порядок всегда от самого нового необработанного (LIFO), в ядре нужен режим `newest_first` |
| Закрытые ЛС | «Пропускать с отметкой» | отметка 🚫 на заявке, `failed` с причиной `privacy` |

Владелец (2026-10-12): «Я всё подтверждаю» → принято: подтверждает отправки сам владелец; интервал — одна отправка в системе раз в 120 с; пилотный лимит 20 в день на аккаунт.

Уточнение владельца: «Отправки только-только первые я контролирую, дальше всё на автомате» → режим `confirm` на первые N отправок (настройка `CONFIRM_FIRST_N`, по умолчанию 20 на систему), затем бот один раз предлагает кнопку «Включить автомат»; в `auto` черновик уходит без подтверждения, если проходит проверки (нет цифр цен/адресов/дат наличия, длина, уверенность), иначе — на ручную проверку; команда паузы доступна всегда.
